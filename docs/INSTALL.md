# 安装与版本交付

本仓库提供游戏源码。需要自行取得 MemoMind App、兼容 SDK / Studio 和 GM Web Bridge 眼镜插件。平台材料、账号和安装包不在 Git 里；具体入口以当前官方 App / Studio 为准。

1. 按 [BUILD.md](BUILD.md) 构建应用和手机 MMPKG。
2. 在 Desktop Studio 导入手机包及官方配套 GM Web Bridge（`com.gm.example.web-bridge`）。保留眼镜包旁的 manifest 与 review 附件。
3. 核对手机应用 `com.memomind.doom.controller`、版本 0.1.5、显示协议声明与眼镜提供能力；声明 preferredPluginId 不会自动实现或安装眼镜端。
4. 选择手机应用和眼镜组件后导出包含两端的组合 ZIP。核对实际 ZIP 中的手机 manifest、眼镜 manifest 和 review，而非仅看下拉框。
5. Studio 生成当前版本安装二维码，在官方 App 的开发者工作台扫码。导出目录里的独立 MMPKG 只是手机端补充文件。
6. 首次启动授权显示、连接事件；进入真实关卡，检查触控、手机 HUD、眼镜画面、暂停和断连恢复。

## 每次更新的交付要求

每次应用更新都直接附上对应版本的**可用安装二维码**，同时保留包版本、组合 ZIP 的 SHA-256 和验证记录。二维码必须指向当前运行的安装服务；过期的开发安装码不放入源码文档作为通用下载入口。

## 局域网排查

手机和电脑需能互相访问。代理/TUN 网卡可能使 Studio 选错地址；确认二维码使用实际 Wi-Fi 网卡地址，排查防火墙、VPN 和代理对局域网的处理。电脑能下载文件不代表手机能连到安装服务，需在手机扫码重试时核对服务端是否收到连接以及完整文件是否传完。

开发扫码通常是临时局域网侧载，并非 GitHub Release 链接或长期公共安装渠道。不要公开本机局域网地址、当前安装二维码、账号状态或加密审核附件。

## 配对证据

既有接受版本曾由 Studio 导出 AB 组合包，并检查两端包字节和 review 哈希。所用旧版 `check_pair.py --bundle` 只理解 review v1/v2，遇到 v3 会失败；不能把这个工具失败改写为通过。公开发布新包时需用支持当前 review 版本的验证器，或明确记录独立的 ZIP / 哈希 / 元数据核对结果。
